# 热点营销工作台 Demo

## 项目背景与目标说明

### 项目背景

电商运营与媒体采编在日常营销中需要持续关注多个平台的新闻热点，再判断热点是否适合借势、挑选关联商品、创作微博文案并审核发布。这些工作分散在不同工具中，人工整理耗时，也容易出现素材与文案错配、重复借势，以及使用高风险新闻进行商品营销等问题。

本项目将这些环节集中到一个工作台，并提供独立后台维护商品、抓取来源、模型配置和提示词。运营人员可以在同一条业务链路中完成选题与内容制作，再通过运行流水和文案评测结果复盘效果。

### 目标用户与使用场景

- **电商运营人员**：在电脑端监控热点，挑选商品，生成多个文案版本，审核后完成模拟发布。
- **媒体采编与内容运营人员**：判断热点的营销适用性，调整表达风格与语调，检查文案的事实、价格和合规问题。
- **运营主管与配置维护人员**：通过后台管理商品库、新闻订阅源和模型参数，查看运营数据，比较不同提示词版本的评测结果。

### 项目目标

1. **贯通营销流程**：实现“新闻抓取 → 建议匹配商品 → 手动补充商品 → 创作文案 → 审核并发送”的完整闭环，同时支持按条件执行的自动流水线。
2. **提升选题与创作效率**：根据热点消费场景计算商品匹配度并说明理由，结合热点、商品与语调生成可供运营挑选的候选文案。
3. **控制借势与内容风险**：拦截禁止借势的新闻，提醒需人工判断的热点，识别重复事件，并通过机器校验、模型评审和自动返工检查文案问题。
4. **保证上下文连贯**：热点或商品变化后，让已有文案和审核状态失效，避免发布与当前素材不一致的内容。
5. **让配置与效果可追溯**：支持配置备份与恢复、操作流水、运营看板以及带提示词快照的评测和 A/B 对比，为后续迭代提供依据。

### 当前原型范围

这是一个用于产品演示、业务流程验证和模型效果调试的 Web 原型。支持本地模拟、本地服务中转和浏览器直连三种模型接入方式；启动本地服务后可抓取公开热榜与新闻订阅源，服务不可用时仍可使用内置数据完成演示。

当前发布操作为**模拟发布**，不会向真实微博账号发帖。配置、流水和评测记录使用本地 JSON / JSONL 文件持久化；浏览器本机存储承担离线配置与回退用途。数据与匹配、模型调用、提示词、去重及评测逻辑拆分为公共模块，供工作台和后台复用，便于后续接入真实业务服务。

纯 HTML/CSS/JavaScript 与 Node.js 内置模块实现，无需安装依赖或构建。

## 打开方式

- 双击 `index.html`：离线演示数据、模拟生成、审核与模拟发布均可使用。工作台右上角“后台”可进入独立后台。
- 在项目目录运行 `node server.js`，再打开 `http://127.0.0.1:8787`：启用真实热榜抓取、服务端配置和流水记录。默认端口 8787，可通过 `PORT` 环境变量更改。

## 后台管理

后台与工作台共用 `style.css` 的颜色变量，不需要单独构建。各页面使用同一套顶栏、分组侧栏、卡片内容区和固定底部操作栏：

| 页面 | 地址 | 当前内容 |
| --- | --- | --- |
| 系统配置 | `admin.html` | 接入方式、服务商预设、接口地址、模型名、浏览器直连密钥、温度、流式开关、测试连接和自动流水线热度阈值。 |
| 提示词模板 | `admin-prompts.html` | 模型角色与写作规范、调用素材模板、单件商品格式、占位符清单、实时预览和独立试运行。 |
| 创作风格与语调 | `admin-styles.html` | 风格名称与要求的增删改、排序，以及主打语调标签管理。 |
| 数据源管理 | `admin-sources.html` | 公开热榜启停、多个自定义 HTTPS RSS / Atom 订阅源、逐源测试和风险说明。 |
| 运营数据看板 | `admin-dashboard.html` | 今日、近七天、近三十天与全部流水指标，自绘图表、商品排行、动态流和 Token 单价配置。 |
| 文案效果评测 | `admin-evaluation.html` | 用例管理、受控并发评测、机器规则、低温模型评审、人工反馈、提示词快照和 A/B 对比。 |
| 商品库 | `admin-products.html` | 商品统计、分页表格、每页条数选择、搜索筛选排序、新增编辑、批量操作、JSON/CSV 导入导出。 |
| 运行记录 | `admin-records.html` | 抓取、文案生成、模拟发布流水汇总、筛选和最近 100 条明细。 |

左侧“本页配置”链接会滚动到当前页面对应区块，“后台页面”链接可在后台页面之间跳转；顶栏和固定底栏都可返回工作台。

所有后台配置页共用保存机制：表单与已保存值不同时，底部操作栏显示“有未保存的修改”；改回原值会自动消除提示。按 `⌘S`（macOS）或 `Ctrl+S`（Windows/Linux）可保存；未保存时刷新、关闭或跳转会触发浏览器原生离开提醒。成功提示会明确写出保存到服务端还是浏览器本机。各可编辑区块右上角可单独“恢复默认”，它先修改当前草稿，仍需保存才会生效。

每个配置页的“备份与恢复”区可导出已保存的整份配置，导出文件不含服务端或浏览器密钥；导入只接受本后台导出的 JSON 格式，先完整校验，再写入当前配置来源。坏文件会显示错误且不更改原配置。服务端每次写入前把上一版文件原样保存为 `data/config.json.bak`，可用“恢复上次服务端版本”回滚；回滚前的当前版本也会被备份。读取服务端文件时会为缺失字段和提示词子字段补上内置默认值，已明确写成空商品库等无效内容仍会被拒绝。可运行 `node verify-config.mjs` 验证这些行为。

后台按“服务端 → 浏览器本机 → 内置默认值”的优先级读取配置，顶栏徽章会显示实际命中的层级。通过 `http://127.0.0.1:8787` 打开且本地服务可用时显示“数据来源：服务端”；双击 HTML 离线打开时，首次会把内置配置写入浏览器存储并显示“数据来源：浏览器本机”。只有浏览器禁止本机存储时才会显示“内置默认值”。保存时，在线模式按本页字段写入服务端并同步浏览器副本，离线模式写入浏览器本机。系统配置与工作台快捷设置使用同一份配置；工作台每次生成前重新读取，后台修改模型名后无需重开工作台。

商品库从同一份配置的 `products` 读取商品；搜索覆盖名称、卖点和标签，统计始终按完整商品库计算，筛选结果数单独显示。价格区间取有效售价的最低和最高值；平均折扣率为每件有有效划线价的商品 `(划线价－售价) ÷ 划线价` 的平均值，不含缺少划线价的旧版自定义商品。旧版内置演示商品会按商品 ID、名称和售价补齐演示划线价。

点“新增商品”或商品卡上的“编辑商品”会打开弹窗，右侧卡片实时显示名称、图标、渐变配色、价格、品类与卖点。编号自动生成且不能重复；名称、图标、品类、售价、原价和至少一个卖点标签为必填。售价与原价均须大于零，原价不能低于售价；字段旁即时显示具体错误，折扣率随价格变化。图标可从表情面板选择或手动输入，背景有 12 种预设，品类支持选择已有值或输入新值。卖点标签按回车添加、点叉删除，建议 2–4 个。保存通过原有三级配置机制写入服务端或浏览器本机；服务端写入前仍会备份上一版，并拒绝重复编号和错误原价。新商品的标签、名称和卖点描述会参与现有场景匹配。卡片由 `src/catalog.js` 在工作台和后台共用，所有商品文本显示前均转义。运行 `node verify-products.mjs` 可核对统计、校验、匹配与转义。

商品列表使用分页表格，默认每页 10 条，可选 5、10、20、50、100 条，本机浏览器记住条数偏好。搜索、筛选和排序后回到第一页；删除或导入导致页数缩减时自动回到有效页码。表格增加“热点引用”列，以“1条”等形式显示引用数量，悬停可查看关联标题；统计范围注明在表格上方，与删除确认共用当前热点快照。每行提供编辑、复制和删除；复制会生成新编号并打开预填编辑弹窗，保存后创建副本，本地商品详情链接会指向副本编号；单件删除也会检查引用并要求确认。支持跨页多选；“选择本页”只操作当前页商品，翻页保留选择；取消勾选商品或“选择本页”即可取消对应选择。批量修改品类可选现有值或输入新品类，保存后列表和统计立即刷新。批量删除需在弹窗中再次确认：后台用与工作台相同的消费场景匹配算法，逐件显示被多少条热点推荐引用及示例热点标题。引用检查覆盖内置演示热点；连接服务时还会读取当前实时热榜，无法读取时会在弹窗注明检查范围。历史抓取热点没有单独持久化，因此不计入这次引用数。删除后这些商品会从后续即时匹配结果中消失。批量结果显示成功数、跳过数和原因；已不存在的商品、品类未变化的商品会跳过；为避免清空商品库，全选删除会被拦下。服务端仍会在每次写入前保留上一版备份。

商品库可独立导出 JSON 或带 UTF-8 BOM 的 CSV。JSON 保留完整商品对象，适合备份迁移；CSV 的主要中文列为“名称、售价、原价、品类、卖点、图标”，卖点以顿号分隔，附加中文列保存编号、卖点描述、背景色、图片、链接、展示模式及原始属性，便于表格编辑后原样回导。CSV 遵循双引号转义规则，可解析字段内逗号、双引号和换行，并转义可能被表格软件当作公式的单元格前缀。旧版商品若未保存原价，CSV 仍会显示内置划线价；回导未修改的行会保留其原始字段结构。导入前会列出缺少表头、缺失必填项、非法价格、重复编号或引号格式错误的行号与原因；只要有一处错误，确认导入按钮就不会出现，原商品库保持不变。校验通过后，运营在预览弹窗确认整库替换；写入沿用服务端优先、浏览器本机次之的保存机制。运行 `node verify-transfer.mjs` 可验证两种格式对当前商品库的完整回导和错误定位。

后台对运行记录等外部数据使用 DOM `textContent`，表单回填使用元素 `value`，不把用户填写的内容拼接为 HTML；新增后台页面也应遵守这一输出约定。

提示词模板使用 `{{占位符}}`。调用素材支持 `{{热点标题}}`、`{{热点摘要}}`、`{{话题标签}}`、`{{商品清单}}`、`{{语调}}`、`{{创作风格}}` 和 `{{风格要求}}`；单件商品格式支持 `{{商品序号}}`、`{{商品名称}}`、`{{商品价格}}`、`{{商品卖点}}`、`{{商品分类}}` 和 `{{商品标签}}`。`{{商品清单}}` 会先用单件商品格式逐条渲染，再以换行拼入调用素材。未识别的占位符原样保留，便于运营在预览中发现拼写错误。模板保存后，重新进入工作台生成文案即可使用新配置；本地模拟还会执行“必须包含「文字」”、Emoji 禁用和字数上限等常用规范，真实模型会收到完整模板内容。

创作风格与语调页可维护风格名称、创作要求及顺序，且至少保留一个风格和一个语调。工作台选择“主打语调”后，点击生成会按风格顺序分别调用模型；每个候选可单独选用、编辑、复制、审核。同一热点和商品组合下，各主打语调分别保留本次页面会话的草稿与候选版本；切回语调会恢复正文、选用版本、机器校验、修正记录和生成耗时/消耗信息。重新生成只替换当前语调的版本；切换热点或调整商品会清空所有语调的旧候选，避免上下文错配。草稿不跨页面刷新保存。手动编辑和“一键修正”会同步保存对应候选的正文、机器校验与修正记录，切回版本时按最新正文重新校验并恢复该版本的记录；修正期间暂停版本切换和正文编辑，更换素材会取消旧修正请求。可运行 `node verify-workbench-candidates.mjs` 验证修正与编辑后的版本及语调回切、语调间草稿隔离、素材变化后的缓存清除，以及旧请求结果隔离。旧提示词模板即使没有新增风格占位符，调用时也会附加当前风格及要求。

提示词页的预览可切换示例热点与表达风格，System 和 User 两块展示本次将发送的完整内容及字数，编辑模板后立即刷新。试运行读取编辑框当前内容；可为本次试运行临时填写模型名，并选择本地模拟、服务中转或浏览器直连。试运行结果只留在当前页面，不写入工作台流水或发布记录。中转模式使用服务端配置的地址与密钥，经 `/api/chat/preview` 发送本次模型名；模拟模式会明确标记结果不能代表真实模型效果。运行结果展示耗时和服务商返回的 token 消耗量，服务商未返回时明确标记。

可运行 `node verify-preview.mjs` 做零外部依赖的端到端验证：脚本在临时目录启动本地模型替身与应用服务，检查流式结果、消耗量、临时模型名、错误翻译和不写流水。真正调用 DeepSeek 或其他服务商时，需要先在服务端配置有效密钥，再从提示词页切换到“本地服务中转”试运行。

## 运营数据看板

从后台“运营数据看板”进入，可切换今日、近七天、近三十天和全部。看板直接读取运行流水：抓取次数为 `fetch` 流水条数，入库条数为每次抓取 `returned` 之和，风险拦截和同批去重分别为 `blocked`、`deduped` 之和；文案生成统计所有 `generate` 尝试，模拟发布只计成功的 `publish`。来源分布累加各次成功来源抓到的原始条目，因此可能高于去重后的入库条数数。商品排行按成功发布所带商品计数。旧生成记录没有模型名时归入“历史未记录模型”，新记录写入实际模型名。

Token 消耗按流水的 `usage` 汇总，包含模拟模式的估算用量；预估花费只计算真实模型调用。单价在看板底部配置，单位为人民币元 / 百万 Token，可分别设置输入、输出以及仅有总量时的单价。默认数值仅为演示参考价，以服务商官网为准，可自行修改。未返回用量的调用无法估算费用。无服务时看板读取浏览器本机留存流水；有服务时读取完整服务端流水。运行 `node verify-dashboard.mjs` 可核对时间筛选、空态与当前真实流水的指标。

## 文案效果评测与返工

后台“文案效果评测”分用例管理、跑评测、历史与对比三视图。用例管理以表格展示名称、热点标题与话题、关联商品与价格、语调、备注和操作；可全选、全不选、新建、编辑、复制和删除。可从内置热点与当前商品匹配库生成种子用例，也可从已有成功发布流水提取热点、关键词与关联商品；相同素材不会重复生成。编辑弹窗可修改名称、摘要、关键词、语调、备注和商品，是否参与评测可在表格中勾选。窄屏下表格可横向滚动。评测任务数 = 已勾选用例数 × 已选风格数 × 重复次数；并发数默认 3、上限 8，叫停会取消进行中的请求且不再派发新任务。每次运行保留当时的 System/User/商品模板、创作风格、评审与返工说明的完整快照，并生成可辨认的短标识。两次运行可按用例与风格比较均分，高亮退步项；明细采用可展开表格，展示字数、规则分、评委分、总分及状态，支持全部展开/收起与「好 / 差」人工标注，备注随结果保存。进度汇总的平均字数按已成功生成的文案计算，包含话题、空格和标点，与规则校验口径一致；历史记录在查看时也会重新计算。 明细右上角可“导出 JSON”，下载当前查看运行的文案全文、字数、逐项校验、模型评审、人工反馈、汇总、运行参数与提示词快照；历史记录同样支持导出。运行期间导出的是点击时已完成结果的快照，失败任务也保留，不含模型密钥。

导出步骤：在“跑评测 → 明细”右上角点击“导出 JSON”；导出历史运行时，先在“历史与对比”点击对应记录。没有明细时按钮禁用。文件为 UTF-8 JSON，文件名包含提示词版本标识和导出时间，便于归档。

| 导出字段 | 内容 |
| --- | --- |
| `kind` / `version` | 文件类型 `hot-marketing-evaluation-results` / 格式版本 `1`。 |
| `exportedAt` | 点击导出时的 UTC 时间。 |
| `run` | 当前运行的编号、时间、模型、接入方式、状态、任务进度和参数。 |
| `run.snapshot` | 本轮使用的提示词与创作风格快照。 |
| `run.summary` | 按本次导出明细重新计算的汇总，包括平均字数。 |
| `run.results` | 文案、字数、评分、逐项校验、模型评审、耗时、消耗、费用和人工反馈；失败项保留状态与原因。 |

“合规修正提示词”由手工模式的“一键修正”和自动流水线共用，字数要求通过 `{{minLength}}` / `{{maxLength}}` 读取当前校验配置，默认 140–180 字（当前工作台最大 180 字）。每轮自动传入 `{{copy}}` 原文案、`{{failures}}` 可修复的失败项及具体原因、`{{products}}` 商品名称/售价/原价/卖点、`{{topics}}` 必须包含的话题标签。未知变量原样保留。旧内置评委与修正提示词自动升级，运营自定义的提示词和字数设置保留；保存前仍备份上一版配置。

`src/evaluation.js` 是页面无关的评测核心，工作台手工模式与自动流程直接复用。机器校验按字数 12、话题标签 12、Emoji 8、广告法违禁词 24、价格真实性 22、结尾互动 8、残留排版 6、商品提及 8 分计权重。违禁词和虚构金额为硬伤；金额同时列出文案金额与素材可用售价/原价。返工只派送字数、话题、违禁词、价格与互动问题，温度默认 0.2；新稿分数没有提高或引入新的硬伤时保留上一稿。手工模式展示逐项结果和“一键修正”；自动流程按配置轮数返工，硬伤或总分低于 75 时转人工复核，返工轮次会进入运行流水。

评委提示词默认采用电商内容评审规范，返回 `relevance`（热点关联度）、`coverage`（卖点与价格覆盖准确度）、`appeal`（传播吸引力）、`tone`（语气自然度）四项 1–5 分整数，以及不超过 40 字的 `comment`。解析与历史明细兼容旧字段 `fidelity` / `naturalness`。模型评审温度默认 0.1；解析器能从前后说明和代码块中提取 JSON，仍无法解析时只标记该条评审失败，总分退回机器分。两项合成权重默认 50/50。模拟模式只演示文案与规则校验，明确不提供真实模型评审，也不代表真实模型效果。输入/输出 Token 单价是可修改参考价，具体费用以服务商官网为准；模型未返回用量时费用可能偏低。用服务端中转做真实评测前，需在 `data/config.json` 填入有效 `apiKey` 并切换 `mode` 为 `proxy`。`node verify-evaluation.mjs` 可复现构造违规文案及一轮返工的分数。

提示词页有“应用强化规范与合规范例”按钮，可把硬性字数、价格与格式约束填入草稿；保存后对同一批用例再跑一轮，历史页即可对照提示词差异和分数。内置创作规范与句式范例同步为 140–180 字；范例 162 字，机器校验 100 分。已保存的创作规范保留原内容，生成与修正均以当前素材为准。已经保存的运营提示词不会被默认值自动覆盖。

## 本地服务接口

以下接口由 `server.js` 提供，默认地址为 `http://127.0.0.1:8787`。写入接口使用 `Content-Type: application/json`。

| 方法 | 路径 | 请求参数或请求体 | 主要返回内容 | 用途 |
| --- | --- | --- | --- | --- |
| GET | `/api/config` | 无 | `{ config, source }`；未配置时 `config` 为 `null` | 读取服务端配置。返回的 `config` 不含密钥，只包含 `keyConfigured` 布尔值。 |
| PUT | `/api/config` | JSON 配置字段，如 `mode`、`provider`、`baseUrl`、`model`、`temperature`、`stream`、`autoThreshold`、`products`、`sources`、`rssFeeds`、`tokenPricing`、`promptTemplates`、`creativeStyles`、`tonePresets`；不接收浏览器密钥 | `{ config, source: "server" }` | 合并并校验配置，写入前备份旧版到 `data/config.json.bak`；空商品库、重复商品编号、原价低于售价、无效订阅地址和单价等配置会被拒绝。 |
| POST | `/api/config/restore` | 无 | `{ config, source: "server" }`；备份不存在或无效时返回错误 | 校验并恢复上次服务端备份，同时保存回滚前的当前版本。 |
| GET | `/api/hot` | 可选查询参数 `force`；只要提供该参数就跳过 2 分钟缓存 | `{ news, sources, blocked, deduped, mode, at, cached }` | 抓取各来源热点。`sources` 包含每个来源的状态、数量、耗时和失败原因；所有来源失败时 `mode` 为 `demo`。 |
| POST | `/api/sources/test` | `{ sources: ["baidu", "ithome"], rssFeeds: [{ id, name, url, enabled }] }` | `{ sources: [{ id, name, status, count, duration, error? }] }` | 对当前草稿中已启用的来源发起一次真实抓取，不改配置，也不使用两分钟缓存。失败源单独返回原因。 |
| GET | `/api/records` | 可选 `all=1`；默认只返回最近 500 条 | `{ records }` | 读取抓取、生成和模拟发布流水；数据看板使用 `all=1` 读取服务端完整流水。 |
| GET | `/api/evaluations` | 无 | `{ cases, runs }` | 读取评测用例、运行快照、明细和人工反馈；无文件时返回空集合。 |
| PUT | `/api/evaluations` | `{ cases: [...], runs: [...] }` | `{ ok: true }` | 校验完整评测数据并原子写入 `data/evaluations.json`，写入前备份旧版。 |
| POST | `/api/log` | JSON；`type` 为 `generate` 或 `publish`，可附 `title`、`keywords`、`products`、`mode`、`model`、`status`、`duration`、`usage`、`copy` | 通常为 `{ ok: true }`；自动发布重复时为 `{ ok: false, duplicate: true }` | 记录生成或模拟发布。新生成流水会写入实际模型名；自动模拟发布前会再次检查三天去重。 |
| POST | `/api/chat` | `{ "messages": [{ "role": "system", "content": "..." }, ...] }` | 根据 `stream` 配置返回 SSE 或完整 JSON | 使用服务端配置的地址、模型、温度和密钥中转 OpenAI Chat Completions 兼容请求；浏览器不会获得服务端密钥。 |
| POST | `/api/chat/preview` | `{ "model": "本次模型名", "messages": [...] }` | 根据 `stream` 配置返回 SSE 或完整 JSON | 后台试运行专用；仅本次覆盖模型名，仍使用服务端地址、温度和密钥，不记录为工作台生成流水。 |
| POST | `/api/chat/test` | `{ "model": "待测试模型名" }` | `{ ok, model, duration }`；失败时 `{ error }` | 用服务端保存的地址和密钥发送一次最小非流式请求，返回上游实际模型名和毫秒耗时；不写入工作台流水。 |

`/api/config`、`/api/hot`、`/api/records` 和 `/api/log` 返回 JSON；错误通常返回 `{ "error": "原因" }`。`/api/chat` 需要在服务端配置密钥，未配置时返回 HTTP 401。以上均为本机原型接口，不包含登录鉴权；服务默认只监听 `127.0.0.1`。

## 安全提示

- **仅在可信的本机环境运行。** 当前接口没有登录鉴权或请求频率限制，虽然服务默认只监听 `127.0.0.1`，仍不应直接暴露到公网或通过反向代理开放给他人。正式部署前需补齐鉴权、权限控制、限流和 HTTPS。
- **优先使用“本地服务中转”保存模型密钥。** 密钥写在不纳入版本管理的 `data/config.json` 中，服务端配置接口不会把密钥返回浏览器。不要把实际密钥写进 `data/config.example.json`、截图或提交记录；如果密钥泄露，应到服务商处轮换。
- **“浏览器直连”会把密钥保存在当前浏览器本机，并直接发给模型服务商。** 只在可信浏览器中使用；共享电脑上演示后应清除该站点的浏览器存储。浏览器跨域限制也可能使直连失败。
- **保护流水、评测数据与抓取配置。** `data/activity.jsonl` 和 `data/evaluations.json` 可能包含新闻标题、商品、生成文案和人工点评；`data/config.json` 可能包含密钥和自定义 RSS 地址。这些文件及各自的 `.bak` 备份都应限制访问。
- **热榜风险标签只是初筛。** 灾难、疫情、战争、犯罪和争议议题的识别依赖规则，可能漏判或误判。正式营销发布前必须由运营人员核实新闻事实、商品关联、文案合规性与来源服务条款；当前“发送”仅为模拟，不会连接真实微博账号。

## 模型设置

后台“系统配置”和工作台右上角“设置”共用同一套参数。可选本地模拟、服务中转或浏览器直连；服务商预设包含 DeepSeek、OpenAI、阿里云百炼和自定义兼容接口。选择预设会填写地址和常用模型名，之后可以手动修改。默认使用 DeepSeek `deepseek-flash`、创作温度 0.85 和流式输出。创作类推荐温度 0.7–1.0，分类与抽取类推荐 0–0.3。关闭流式输出时，模型完整返回后工作台仍逐字展示正文；思考内容不会混进正文。

服务中转时，将密钥填入 `data/config.json` 的 `apiKey` 字段并重启服务。浏览器的配置保存请求不会覆盖服务端密钥，服务端也不会把密钥返回浏览器。浏览器直连密钥仅保存在当前浏览器本机，部分服务商可能因 CORS 限制而无法直连。后台“测试连接”会发送一次最小非流式请求；中转模式使用服务端已保存的地址与密钥，修改接口地址后请先保存再测试；模拟模式会明确提示没有连接真实模型。

配置读取优先级为服务端 → 浏览器本机 → 内置默认值。设置页保存至服务端时，上一版写入 `data/config.json.bak`，空商品库等无效配置会被拒绝。`data/activity.jsonl` 记录抓取、生成和模拟发布流水。服务未运行时，前端保留本机流水以支持三天去重。

## 工作台两种模式

顶部可在“手工模式”和“自动模式”之间切换。两种模式共用热点、商品库、模型配置和操作流水；当前“发送”均为模拟，不会向真实微博账号发帖。

| 模式 | 操作流程 | 适用场景 |
| --- | --- | --- |
| 手工模式 | 按“新闻抓取 → 建议匹配商品 → 匹配商品 → 创作文案 → 审核并发送”五步操作。运营人员选择热点、采纳或补充商品、生成或修改文案，再人工审核与模拟发布。禁止借势热点无法选中；需人工判断和三天内发布过的热点会提醒。更换热点会清除已选商品与文案，更换商品会使旧文案和审核状态失效。 | 需要人工选题、调整商品和审核文案时。 |
| 自动模式 | 进入后立即运行，此后每两分钟复查；可手动“立即运行一次”或暂停。流水线依次检查风险、数字热度、三天内发布记录和商品匹配。匹配度至少 90% 才生成文案，之后检查文案风险、长度和话题标签，再模拟发送并留痕。页面展示每条新闻的跳过原因和自动发送清单。 | 监控大量热点并自动筛选安全、相关且达到热度门槛的选题时。 |

自动模式的最低新闻热度默认 500 万，可在自动页调整；配置读取优先级仍为服务端 → 浏览器本机 → 内置默认值。离开自动模式或点击“暂停自动模式”会停止当前轮询。

## 热点去重规则

1. **计算标题相似度。** 先去掉空格、标点和符号并转为小写。标题完全相同记为 `1`；如果较短标题至少有 8 个字符且被另一标题完整包含，记为 `0.95`；其余标题使用相邻两个字符组成的集合，按 `2 × 共同双字数 ÷ 两个集合的双字数之和` 计算相似度。达到 `0.55` 即视为同一事件的相似报道。
2. **同一批抓取结果合并。** 按来源给出的排名由前到后处理，相似报道只保留排名靠前的一条，并汇总不同来源。新闻卡片会标注“几个源在报”；抓取结果还会显示本轮合并的重复数量。
3. **与历史发布记录比较。** 只比较最近三天的 `publish` 流水，标题相似度达到 `0.55` 就视为近期已发过。手工模式在卡片上提醒，但允许运营人员有意再次选题；自动模式会跳过并显示原因。服务端在写入自动发布流水前再次检查，避免多个页面同时重复发送。

去重判断以标题为依据，不能保证识别所有不同措辞，也可能把高度相似但不同的事件合并；发布前仍需人工核对。

## 数据与风险

默认抓取百度热搜、微博热搜、知乎热榜及 IT之家 RSS。在“数据源管理”可逐个启停内置来源，添加、停用或删除多个自定义 HTTPS RSS / Atom 订阅源。来源配置存于 `sources` 和 `rssFeeds`；旧版 `customRssUrl` 会自动读成一条可管理的订阅源。测试按钮对当前草稿逐源真实抓取，显示条数、耗时及失败原因；保存后工作台抓取只请求启用项。单源失败不会中断其它源；每源有 7 秒超时，工作台整体缓存 2 分钟。所有来源失败时明确显示演示数据。抓取接口仅用于原型演示，正式上线应使用官方开放平台或商业舆情服务，并遵守平台 robots 协议及服务条款。

灾难、疫情、战争和犯罪类标题禁止借势；时政、财经和争议议题需人工判断。规则是保守的关键词初筛，正式使用须增加编辑审核。

核心模块位于 `src/data.js`、`src/matching.js`、`src/dedupe.js`、`src/prompts.js`、`src/llm.js`、`src/auto.js`；浏览器以普通脚本加载，Node 服务直接复用数据与去重模块，双击文件无需构建。

微博审核预览会展示每件已绑定商品的图片、价格和可点击的商品详情链接。内置商品图片保存在 `assets/products/`，默认链接进入本地演示详情页，离线也能打开。商品库 JSON 可为每件商品配置 `image`（本地 `assets/products/*.svg` 或 HTTPS 图片）和 `url`（HTTPS 商品链接）；未配置图片但填写 `emoji` 时会本地生成表情示意图，否则显示通用占位图。
